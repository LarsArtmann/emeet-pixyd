## e) WHAT WE SHOULD IMPROVE

1. **Machine-state gate before any benchmark/perf claim.** `uptime` first; if load > ~4, don't run ns-level benches at all. Cost when skipped: ~6 min + near-miss false verdicts (§d.1).
2. **Verify gates against the FORMATTER's output, never in isolation.** Order: `dprint fmt` → run the lint with its exact CI config → commit. The golangci-pin incident taught "verify the exact version"; this session adds "verify the exact pipeline position" (§d.2).
3. **Treat package-manager runs as config mutations.** Every `pnpm/npm/update` command gets an immediate `git diff` review of manifest files (caught the pnpm workspace mutation in minutes; without the review it ships silently).
4. **One decisive benchmark protocol.** Quiet window, n≥6 (benchstat's own CI threshold), full 9-bench set, once — instead of exploratory re-runs that pollute the data directory.
5. **Dismiss stale LSP diagnostics on sight.** The clean-cache golangci-lint run is the only trustworthy verdict (documented since the 2026-10-31 sweep); mid-session LSP warnings that contradict a fresh lint are noise and should be treated as such immediately.
6. **Pin-site minimization.** The firebase-tools version now lives in three places (deploy step, cache key, setup doc) tied by a documented protocol; a single source (one variable echoed into the others via a check step, or a CI assert that all three match) would kill the drift class. §f.31 carries the related AGENTS split brain.
