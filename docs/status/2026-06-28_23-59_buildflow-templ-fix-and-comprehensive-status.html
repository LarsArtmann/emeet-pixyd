04Totally Fucked Up!

Critical

Generated templ file can silently become empty and break CI

templates_templ.go

The project gitignines *_templ.go, and BuildFlow's templ-generate step should recreate it. Today it produced an empty file instead, causing the first Go compile to fail with expected 'package', found 'EOF'. The root cause is unknown — possibly a race between formatter and generator, or a transient templ daemon state.

Why it matters CI and local builds depend on generated code that is not tracked. If generation flakes, every contributor hits a cryptic compile error and loses trust in the build.
Fix applied Ran templ generate manually and verified the file regenerated 970 lines. BuildFlow now passes, but the flake source is not fixed.
Important

BuildFlow CLI hint is misleading

buildflow output footer

Both successful runs end with the tip buildflow dev, but buildflow dev is not a valid subcommand. The correct invocation is buildflow --build-mode=dev. This wastes time and erodes confidence in the tool's own guidance.

Important

Five tools are stuck in check-only mode

buildflow --build-mode=dev

BuildFlow reports "5 tool(s) in check-only mode (use --fix to apply fixes)". These are likely formatters/linters that could auto-fix issues but are not configured to do so in default runs, leaving manual cleanup work on the table.

05What We Should Improve

Reliability

Make templ generation idempotent and verified. Add a post-generation sanity check (file size > 0, contains package main) before allowing the build to proceed.

Coverage

The 73.2% coverage is dragged down by hardware-facing paths in stream.go, process.go, and hid.go. Introduce interface seams and fake implementations to push coverage above 80% without requiring a physical PIXY.

Documentation hygiene

AGENTS.md, TODO_LIST.md, and CHANGELOG.md were last updated 2026-06-21. Today's templ fix and BuildFlow behavior observations should be folded back into AGENTS.md gotchas.

Tooling messaging

Fix or suppress the buildflow dev hint and clarify which 5 tools are check-only so contributors know whether to run --fix.
