04Totally Fucked Up!

Nothing is totally fucked up right now

The build passes, tests pass, lint is clean, and the Nix flake builds. The closest thing to "fucked" is a class of latent build-tool hazards that have bitten us once and could bite again:

  • templ generate can silently produce an empty *_templ.go file, breaking Go compilation with an EOF error at line 1.
  • buildflow's success footer recommends buildflow dev, which is not a valid subcommand; the correct invocation is buildflow --build-mode=dev.
  • go.sum drift was introduced by the pre-commit hook in the previous session and is currently unstaged; no decision has been made to commit or revert it.
Latent Risk

templ generation can produce empty files

build pipeline / templ v0.3.1020

During the previous session, templates_templ.go existed on disk (42,968 bytes) but the Go compiler saw EOF at line 1. Running templ generate fixed it. We do not know the root cause, so it could recur on CI or a fresh clone.

Fix Add a post-generation validation step that checks every *_templ.go file parses as valid Go; fail the build if any file is empty or unparseable.

05What We Should Improve!

High Impact

Finish the interface extraction trilogy

Architecture Phase 4

We have HIDDevice and CommandRunner, but ProcessInspector, UeventListener, and a unified Commander facade for all subprocesses are still TODO. Completing these would make the daemon fully testable without real /proc, netlink, or external binaries.

High Impact

Fake-device test harness

Testing Phase 6

Many tests still default to real /dev/hidraw7 and /dev/video0 paths and rely on no-op options to avoid hardware calls. A fake HID device and fake video node would let us test the real HID/V4L2 code paths deterministically and raise coverage on stream.go, process.go, and hid.go.

User-Facing

Mobile-responsive layout

Web UI / static/style.css

The glassmorphism dashboard looks good on desktop but has never been verified on small screens. The PTZ sliders and action cards will likely need stacked layout and larger touch targets.

Quality

PTZ readback accuracy

ptz.go / cache.go

After a PTZ set, the cache is updated with the requested value, but if the hardware rejects or rounds the value, the UI displays a lie. Either poll-after-delay or maintain authoritative in-memory state with explicit sync events.

Nice to Have

Trim prometheus/client_golang

go.mod

Only promhttp.Handler is used from the Prometheus client. Removing it would simplify the dependency graph, but requires reimplementing or importing a tiny HTTP handler.

Nice to Have

Domain-type consolidation

internal/pixy

SSEEvent and toastType still live in the web layer; moving them to internal/pixy would keep domain types in one place and make the SSE contract explicit.

07Top #1 Question I Cannot Figure Out Myself

Open Question

Why did templ generate produce a file that looked valid on disk but caused Go to see EOF at line 1?

templates_templ.go / build pipeline / 2026-06-28

The file was 42,968 bytes according to the filesystem, yet go build and the race test failed with templates_templ.go:1:1: expected 'package', found 'EOF'. Regenerating with templ generate produced 970 lines of valid Go. No process crashed, no disk-full condition was reported, and the source templates.templ was unchanged and valid.

I cannot reproduce it on demand, and I do not know whether it was:

  • a templ CLI bug (truncated/empty write without error),
  • a filesystem race where a previous incomplete write was partially visible,
  • a Nix / build sandbox artifact,
  • or something else entirely.
What I need Guidance on whether to add a defensive build-time check, file an upstream templ issue, or instrument the preBuild step. This is the one risk that could silently break CI or fresh contributors without warning.
