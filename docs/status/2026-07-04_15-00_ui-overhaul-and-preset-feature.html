Design Smell

Preset Name in URL Path — No Sanitization

handlers.go:298-341 — handlePresetSave/Load/Delete

Preset names go directly into URL paths (/api/preset/save/{name}). The Go net/http router decodes {name} from the path, but there's no validation that the name is URL-safe. encodeURIComponent in JS handles most cases, but CLI/socket callers could pass arbitrary strings. A name like "../../../etc/passwd" would be rejected by the router (path traversal), but names with spaces, slashes, or Unicode are underspecified.

06What We Should Improve

Type Safety: Preset Name

Presets use raw string everywhere. Should be a branded type PresetName with validation (Valid() checking length, allowed chars). Prevents invalid names at compile time.

View Model Separation

webStatus mixes domain state with view concerns (Toast, ToastType, LastSynced). Should split into domainStatus + viewModel wrapping it.

Preset Limit Constants

maxPresets = 16 lives in commands.go (package main). The template references it directly. Should move to pixy.MaxPresets in the domain package so both layers import from one place.

CSS File Size

style.css is 1,510 lines — large for a single file with 6 cards. Could be split by component (preview, mode-cards, ptz, presets, toast, responsive) but the single-file approach matches the existing pattern. Not urgent, but watch.

Preset Name Collision on Overwrite

Saving a preset with an existing name silently overwrites. No confirmation. Should either warn or show a toast like "Updated preset 'home'".

Snapshot Error Handling

/api/snapshot returns 503 when no frame is available. JS catches this but shows generic "Snapshot unavailable". Should distinguish "camera offline" vs "no frame ready, try again".

08Top Question I Cannot Answer

The nix flake check problem: nix flake check fails because the lint derivation runs templ generate in a sandbox where the templ binary isn't on PATH. The package build itself uses proxyVendor = true and a preBuild hook that runs templ generate — this works. But the flake check's lint step has a different derivation structure and fails with FATAL: $$f empty after templ generate.

I cannot determine: Should the fix be (a) adding templ as a nativeBuildInput to the lint check derivation, (b) restructuring the flake to share a common pre-build step, or (c) disabling nix flake check for the lint target and relying on CI's GitHub Actions instead? The nix sandboxing model makes it hard to debug without understanding the intended flake architecture. This was pre-existing and I chose not to touch it since proxyVendor was deliberately chosen per AGENTS.md.
