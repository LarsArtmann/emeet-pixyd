## e) WHAT WE SHOULD IMPROVE

### Architecture

1. **`Commander` interface is the #1 blocker for testability.** `process.go`, `v4l2.go`, and `handlers.go` call `exec.CommandContext` directly — 8+ functions are untestable without hardware. This requires a single atomic commit: interface + real implementation + Daemon field + all callers + tests.

2. **`handleCommand` cyclomatic complexity = 20.** A dispatch table (`map[string]handlerFunc`) would drop it to ~5 and make each command independently testable. But this is a readability win, not a correctness fix.

3. **Global metrics state.** `promExporter`, `metricInCall`, `metricAutoMode`, `metricCameraState` are package-level vars. Moving into `webServer` would make tests hermetic — but the current `init()` + `sync.Once` pattern works and doesn't cause issues in practice.

4. **`Daemon` struct has many concerns.** HID, V4L2, process detection, HTTP, socket, debounce, PTZ cache. Extracting interfaces would help, but each extraction must be atomic and justified by a concrete test benefit.

### Code Quality

5. **Error string matching in handlers.** `strings.HasPrefix(resp, "error:")` should be `errors.As(CommandError)`. Small fix, high type-safety value.

6. **CRLF in integration tests.** Silent source of bugs. `.gitattributes` with `*.go text eol=lf` would prevent recurrence.

### Testing

7. **69.8% coverage ceiling.** 15 functions at 0% — most require hardware or subprocess exec. `Commander` interface alone unlocks +8-10%.

8. **No benchmarks.** Hot paths (`extractJPEGFrame`, `parseHIDResponse`, `updateMetrics`) have no perf regression detection.

9. **`Run()` at 0% coverage.** The main event loop is 101 lines of orchestrating goroutines. Hard to unit test directly — decomposition into smaller methods would help.

### DevEx

10. **`golangci-lint fmt` is a footgun.** Documented in AGENTS.md. Never run it.

## g) Top Question

**Should the `Commander` interface live in `internal/pixy/` or `main`?**

- **`internal/pixy/`**: Consistent with `pixy.SendCommand`. Test helpers in pixy_test.go could use mock commanders.
- **`main`**: Only used by process.go, v4l2.go, handlers.go. Moving to pixy risks a dependency on `exec`.
- **Recommendation**: Keep in `main`. The interface is a daemon implementation detail, not a shared abstraction. If `pixy.SendCommand` needs testability later, extract a `SocketCommander` separately.
