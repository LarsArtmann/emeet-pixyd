04Totally Fucked Up

Nothing in the code is fucked up — the build is green, tests pass, lint is clean. But two things are worth calling out as process failures:

F1 · makezero: always:true shipped broken

Commit 14600fb ("chore: upgrade Go to 1.26.4 and update dependencies") added makezero: { always: true } to .golangci.yml. This immediately produced 9 false positives on every make([]byte, N) I/O buffer in the codebase (hid, socket, uevent, stream, cache, ipc). The commit message did not mention this change, and it broke nix flake check.

Root cause: Either an automated tool (buildflow's golangci-lint-auto-configure) flipped it, or a copy-paste from a template. The always: true mode is wrong for any project that uses io.Reader.Read() — which is every I/O project.

Fixed this session. Flagged in AGENTS.md with an explicit "Do NOT set always: true" note.

F2 · TODO_LIST.md stale on Commander DOC DRIFT

TODO_LIST.md Phase 4 (#21) and Phase 9 (#71) both list "Extract Commander interface" as ⬜ TODO. But commander.go exists, deps.go wires CommandRunner, and commits aa07cbe + 7642147 implemented and extended it. The doc was never updated.

Why it matters: A status report or planning session reading TODO_LIST.md will believe 3+ hours of work remains that is actually done. This is exactly the "split brain" the project tries hard to avoid.

Not fixed this session — user did not request doc edits beyond AGENTS.md. Recommend fixing in a follow-up commit.

Fake device harness — the coverage multiplier 28% of the root package is uncovered because it needs hardware. A fake HIDDevice + fake video4linux sysfs tree (the probe tests already do this!) would unlock coverage for hid.go, stream.go, device.go sync paths.

5
Reduce indirect dependency surface 13 indirect deps come from prometheus/client_golang for just promhttp.Handler. OTel exporter may offer an HTTP handler directly. Worth a spike.
6
Hardware-in-the-loop CI tier A self-hosted runner with a real PIXY (build-tag hardware) would catch regressions that unit tests structurally cannot. Even a manual go test -tags hardware run before releases adds confidence.
7
Consolidate status reports docs/status/ has 10 markdown snapshots + this HTML. Consider an index or moving old ones to archive/ to keep the directory scannable.
8
CHANGELOG not updated for 0.3.x CHANGELOG still shows [0.1.0] as the latest dated release at the bottom, but version = "0.3.1" in flake.nix. The unreleased section is rich but never cut into a tagged version. Consider tagging 0.3.1.
