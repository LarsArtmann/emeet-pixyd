02Phase 1: Foundation (1% → 51%)

1

Add datastar-go dependency

go get github.com/starfederation/datastar-go — MIT licensed, maintained by DataStar creator. Only transitive dep: valyala/bytebufferpool. Reexported via go.branded-id pattern (public proxy, no GOPRIVATE needed).

2

Download datastar.js

Download DataStar v1.0.2 (11.76 KiB) from CDN to static/datastar.js. Self-hosted, embedded via //go:embed. Replaces the 49 KB htmx.js.

3

Refactor sse.go

Keep Broadcaster struct, Subscribe(), Unsubscribe(), Broadcast() (application-level pub/sub). Delete sseStream, newSSEStream, writeSSEEvent, splitSSELines (replaced by SDK). Change SSEEvent payload from {Event, Data string} to carry a rendered HTML fragment or a patch function.

4

Create renderTempl helper

Helper function that renders a templ component to a string (using templ.RenderToBuffer or similar). Needed because sse.PatchElements() takes a string, not a templ component.

5

Convert handleEvents handler

Replace newSSEStream(w, r) with datastar.NewSSE(w, r). Send connected event via sse.PatchElements() or sse.PatchSignals(). Forward broadcaster events as PatchElements calls with rendered HTML fragments.

6

Update page() template

Replace <script src="/static/htmx.js"> with <script type="module" src="/static/datastar.js">. Keep app.js for now (snapshot + preview only — will be slimmed in Phase 3).

03Phase 2: Core UI Migration (4% → 64%)

7

Convert statusPanel() root

Remove hx-get="/panel", hx-trigger="refresh from:body", hx-swap="outerHTML", hx-indicator="#status-panel". DataStar morphs elements by ID automatically — no swap directive needed. The panel refresh is driven by SSE PatchElements from the backend.

8

Convert action() handlers

Change templ.Handler(statusPanel(status)).ServeHTTP(w, r) to sse := datastar.NewSSE(w, r); sse.PatchElements(renderTempl(statusPanel(status))). This sends the panel as an SSE patch — DataStar morphs it by ID instead of swapping the entire div.

9

Convert cameraModeCard()

Replace hx-post="/api/mode/track" + hx-target="#status-panel" with data-on:click="@post('/api/mode/track')". DataStar patches the response elements by ID automatically.

10

Convert audioSegment()

Replace hx-post="/api/audio" + hx-vals='{"mode":"nc"}' with data-on:click="@post('/api/audio', {signals: {mode: 'nc'}})". DataStar sends signals as JSON body; server reads via datastar.ReadSignals().

11

Convert control buttons

Center, sync, probe, gesture, auto: each gets data-on:click="@post('/api/center')" etc. Remove all hx-target="#status-panel".

12

Convert PTZ sliders

Replace hx-post="/api/ptz/pan" + hx-trigger="input changed delay:300ms" + hx-target="#ptz-pan" + hx-swap="outerHTML" with data-bind:pan + data-on:input__debounce.300ms="@post('/api/ptz/pan', {signals: {value: }})". The slider value is a reactive signal — no manual parameter injection needed.

13

Convert PTZ radar

Replace the 27-line updateRadar() function in app.js with reactive CSS: data-style:--pan-x="@fit(, -150, 150, 0, 100) + '%'", data-style:--pan-y="@fit(, 90, -90, 0, 100) + '%'", data-style:--zoom-pct="@fit(, 100, 150, 30, 80) + '%'". The radar updates live as signals change — zero server round-trips.

14

Convert toasts

Server patches <div id="toast-container"> via sse.PatchElements(). Delete the 14-line showToast() function from app.js. The toast container is morphed (not swapped), preserving other toasts in flight.

15

Convert preset section

Preset load: data-on:click="@post('/api/preset/load/home')". Preset delete: data-on:click="@post('/api/preset/delete/home')". No hx-target needed — DataStar morphs by ID.

08Safety Constraints

DO NOT TOUCH: MJPEG Preview Stream

The /api/stream endpoint and the preview <img> error recovery in app.js are orthogonal to the frontend framework. DataStar does not manage MJPEG streams. The 48-line preview recovery block in app.js stays as-is.

DO NOT TOUCH: Snapshot Download

The /api/snapshot fetch + blob download + toast on success/failure is a plain fetch API call. It does not use HTMX or DataStar. The 33-line snapshot block in app.js stays as-is.

DO NOT TOUCH: Daemon / HID / PTZ / Device Logic

All backend Go logic (daemon lifecycle, HID protocol, V4L2 PTZ commands, device probing, uevent handling, call detection, NixOS module, CLI, socket) is entirely untouched. Only the presentation layer changes.

Verschlimmbesserver warning: Do NOT attempt to "improve" the daemon, HID protocol, or backend logic during this migration. The scope is strictly the presentation layer. Mixing concerns will introduce bugs.

Key Benefits

+
Delete 979 lines of compensating code 510-line app.js → ~80 lines. 179-line sse.go wire-format → 0 (SDK). 370-line sse_test.go → ~60 (Broadcaster only).
+
Automatic focus preservation DataStar morphs only changed DOM nodes. No more preSwapFocusId save/restore. Sliders, inputs, and focus state are preserved by default.
+
Fine-grained updates Instead of re-rendering the entire statusPanel on every action, handlers patch only what changed. Less network, less CPU, less flicker.
+
Client-side reactivity PTZ radar, slider values, and mode highlighting become reactive signals. No server round-trip for display updates.
+
4x smaller JS payload HTMX v2.0.9 is ~49 KB. DataStar v1.0.2 is 11.76 KiB. Faster page load, especially on the local network.
+
Native SSE with built-in retry DataStar handles SSE reconnection, backoff, and tab visibility automatically. No more 30-line custom connectEvents() in app.js.
+
Proven stack DataStar creator's own reference project (1a5s-datastar) uses templ + DataStar + Go. 321 LOC for a full CRUD app. The pattern is exactly what emeet-pixyd needs.
