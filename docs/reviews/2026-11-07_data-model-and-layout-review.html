01Findings

Root cause #1 — Intent and observation share one enum

pixy.CameraState carries three user-desired modes plus StateOffline, a connectivity observation. The persistence invariant ("offline never reaches disk") is enforced by runtime twin-normalization in loadState and saveState instead of by the type system.

Root cause #2 — Empty string as state

Optionality is encoded as "" across Battery, Model, VideoDev, HidrawDev, UnsupportedHint, Toast, LastSynced and State.TrackMode. Boundaries validate, but every consumer re-checks emptiness, and the one dangerous case — TrackMode "" meaning "reads back as face" — is an implicit default hidden in an accessor.

Root cause #3 — View proliferation + a duplicated collapse rule

Four shapes of the same truth (statusSnapshot, webStatus, statusResponse, waybarJSON) and two hand-rolled copies of the "human surfaces collapse intent → offline when no video node" rule (waybar.go:49–51 and device.go:481–490 in getStatus — one substitutes the value, the other early-returns a different format).

The fix in one sentence

Split the desired mode into its own alias type, brand the USB product ID, type the degraded-reason and track-mode strings, and extract ONE display-collapse helper — six additive migrations, all JSON-stable, none blocking.

02Issue Cards

Important

I1 — CameraState conflates desired mode with connectivity

internal/pixy/pixy.go:62–100, state.go:74–88 + 129–144, waybar.go:48–51

State.Camera persists the user's intent; StateOffline is a connectivity observation that v1 files used to (wrongly) persist. ADR 2026-10-01 fixed the persistence split-brain, but the type still lets any CameraState variable hold an observation. The invariant is re-enforced at every boundary: ValidDesired() filtering, load-time normalization to privacy, save-time normalization to privacy — three runtime guards for a fact the compiler could hold.

Fix type DesiredCameraMode string with exactly {DesiredIdle, DesiredTracking, DesiredPrivacy}; State.Camera DesiredCameraMode; a single func (m DesiredCameraMode) CameraState() CameraState projection for display surfaces. JSON bytes are unchanged ("idle"/"tracking"/"privacy"), schema version stays 2, and the twin normalization collapses to zero lines.
Important

I2 — The offline-collapse rule is hand-rolled twice

waybar.go:49–51; device.go:480–490 (getStatus)

Waybar substitutes the camera value inline; the CLI status line early-returns a whole different format string with hard-coded zeros. Two copies of one display rule will drift the next time a human surface is added (a third already exists in spirit inside the web panel's offline banner). This is also finding #2's evidence: the rule exists because intent and connectivity are separate concepts wearing one type.

Fix One helper in internal/pixy: func DisplayCameraState(online bool, desired DesiredCameraMode) CameraState. Both surfaces call it; a table-driven test pins the rule. (Verified: no shared helper exists today — grep for StateOffline in non-test root files finds only the two hand-rolled sites.)
Important

I3 — USB product IDs are raw int64 while process IDs are branded

internal/pixy/model.go:22–78, 97–120; internal/pixy/config.go:35; ids.go

The codebase brands process PIDs (id.ID[pidBrand, int]) and PipeWire source IDs — but USB product IDs flow as bare int64 through the device registries, ResolveProductID, Config.ExtraProductIDs, and the uevent parser. Two unrelated ID spaces (process vs USB) are one int64 substitution bug away from each other.

Fix type USBProductID int64 + named constants + a ParseUSBProductID(string) (USBProductID, bool) that owns the hex parsing now inlined in ParseExtraProductIDs. Alias branding: zero overhead, registry keys become self-documenting.
Important

I4 — State.TrackMode is a string beside a typed enum it mirrors

internal/pixy/pixy.go:288–296, 314–333; internal/pixy/v2head.go:441–495

TargetTrackMode is a verified byte enum with canonical strings ("none"/"face"/"halfbody"/"fullbody") — yet the persisted field is raw string, with "" meaning "never set, reads back as face" encoded in EffectiveTrackMode(). State.Valid() re-parses the string on every load to recover the type safety the enum already provides.

Fix type TrackModePref string (same canonical strings, zero value = unset stays) + func (p TrackModePref) Effective() TargetTrackMode moved next to the enum. Optional hardening: an UnmarshalJSON that rejects unknown strings at decode time instead of at Valid() time.
Nice to have

I5 — Degraded reasons are untyped strings with a prefix protocol

degraded.go:12–43

markDegraded(reason string) accepts anything; the reason space is "one of two constants" or "extdep:<binary>" — a two-variant union encoded as a string prefix. A typo'd reason key silently creates a new degradation class no consumer knows.

Fix type DegradedReason string with the two fixed constants and ExternalDepReason(binary string) DegradedReason owning the prefix. JSON/wire strings unchanged.
Nice to have

I6 — PresetMap trusts its keys

internal/pixy/pixy.go:497–524

PresetMap map[string]PTZValues has Get/SortedNames/IsFull but no validated mutator; ValidatePresetName guards write sites by convention. JSON unmarshal or a careless literal can insert names that violate the documented invariants (≤16, ≤32 runes, no path separators).

Fix Add func (p PresetMap) Set(name string, v PTZValues) error that runs ValidatePresetName + IsFull, and route all write sites (CLI, preset push, web) through it. Keep the map type for JSON stability.
Nice to have

I7 — Machine contracts carry display strings

handlers.go:177–193 (statusResponse.Battery string)

The shell-widget API's battery field is a formatted display string in a contract documented as a stable public interface. Widgets that want to style charging state must parse text. Same class: Reasons []string in statusResponse (fixes itself once I5 types DegradedReason — the strings stay).

Fix Additive first (ADR 2026-09-28 precedent): batteryPercent,omitzero + batteryCharging,omitzero beside the legacy string; update quickshell.mdx; retire the string only in a future schema generation.
Considered & rejected

I8 — SpeedValues / PTZValues near-duplication

internal/pixy/pixy.go:335–416

Two axis-triples (float32 preferences vs int positions) with shared generic plumbing (axisGet/axisSet[V]). A generic AxisValues[V] would unify the shape but erase the domain distinction between "what the user prefers" and "where the camera is" — the exact conflation this review exists to remove. Rejected: premature generalization; the shared helpers are the right altitude.

04The Vision

This model's job: hold user intent durably across unplug, reboot and firmware resets, while observing hardware truth separately — and render both correctly on four surfaces (CLI, web, Waybar, shell-widget API) without the two ever bleeding into each other. The five core entities: DeviceIntent (camera / audio / gesture / track / speeds), Connectivity (video + HID presence), DeviceIdentity (model / family / USB product ID), AxisGeometry (PTZ positions and limits), and Observations (battery, in-call, update, degradation). The invariants that must always hold: persisted camera ∈ desired set; all persisted enums valid; presets ≤ 16 with valid names; zero speed = firmware default; display shows offline iff no video node. Today all five invariants are runtime-enforced; the target model moves three of them into the type system and single-sources the other two.

05Target Data Model (Go)

// Desired intent — what the user chose. Never carries connectivity.
type DesiredCameraMode string

const (
    DesiredIdle      DesiredCameraMode = "idle"
    DesiredTracking  DesiredCameraMode = "tracking"
    DesiredPrivacy   DesiredCameraMode = "privacy"
)

// Display projection — the ONE place the collapse rule lives.
func DisplayCameraState(online bool, m DesiredCameraMode) CameraState {
    if !online {
        return StateOffline
    }
    return CameraState(m)
}

// State.Camera becomes intent by construction — load/save normalization deleted.
type State struct {
    // ...
    Camera DesiredCameraMode `json:"camera"`
}

// Identity — no more bare int64 in the device registry.
type USBProductID int64

const (
    ProductIDOriginal USBProductID = 0x00c0
    ProductID2K       USBProductID = 0x0118
)

// Persistence — typed preference, canonical strings on disk unchanged.
type TrackModePref string // "" = never set; Effective() → TrackFace

// Degradations — closed vocabulary + owned prefix union.
type DegradedReason string
const (
    DegradedWebServer   DegradedReason = "web-server"
    DegradedSocketAccept DegradedReason = "socket-accept"
)
func ExternalDepReason(binary string) DegradedReason // "extdep:" + binary

Design rule applied throughout: alias branding (not struct wrappers) because every zero value must remain JSON-trivial and disk-compatible — the pattern table's "zero value valid? yes / JSON trivial" column decides. Struct wrapping is reserved for cases needing construction-time validation, and none of these survive unmarshal without it anyway.

08Architecture Context — combined with this session's layout verdict

Layout verdict (go-modularize Unix gate, this session)

Flat single-module root stays: 2 packages, `internal/pixy` passes direction/surface but fails the pipe test (no named second consumer), root `main` is one cohesive daemon package. Real sub-packages (hid/stream/web) are blocked by the god-struct `*Daemon` and the same-package lock-order pins — and the type fixes in this review (I1/I3/I5 move intent, identity and degradation vocabulary INTO `internal/pixy`) are exactly the preparation that makes a future hidTransport/streamServer decomposition mechanical. Types first, packages later. Full verdict recorded in docs/adr/2026-11-07_flat-layout-modularization-gate.md.

Conclusion

"The state file already tells the truth; the types are catching up." emeet-pixyd's data model is well above the Go median — branded IDs, evidence-graded protocol types, strict JSON, exemplary error families. The remaining rot is one systemic theme wearing four masks: intent and observation not yet separated in the type system. Five additive migrations, roughly one day, zero persisted-file changes, and the compiler holds the invariants that three runtime guards hold today.
